## 三、基线评测设计（阶段 2）

> ✅ **基线已完成（2026-11-05）**，正式结果与训练验收标准见 [基线结果存档.md](基线结果存档.md)。
> 训练靶子确认：分级知识（4.8%/14.3%）、毒性误标（60%/25%）、think 泄漏（100%）为三大主攻方向。

### 3.1 两层基线

| 层 | 环境 | 用途 | 性质 |
|---|---|---|---|
| 粗基线 | 本地 Ollama `qwen3.5:9b`（Q4 量化） | 人工抽检 ~20 条，看底座幻觉模式，确定评测重点 | 定性，不进对比表 |
| 正式基线 | L20 上 BF16 原权重（vLLM/transformers） | 全量 test 393 条，进对比表 | 定量 |

量化版知识召回有损，粗基线分数**不得**作为对比依据，论文/报告只引用正式基线。

### 3.1a 执行决策（2026-11-04 定）

**基线评测在远程服务器做，vLLM 离线批处理模式（`LLM` 类），不做 `vllm serve` 部署。**

- 有效性：微调后模型将用 vLLM 评测（LoRA adapter 原生支持），基线必须在同精度（BF16）、同模板、同解码参数下跑；本机 Ollama Q4 量化 + 自带模板 = 不可比，故本机只保留人工抽检用途（可挪到服务器顺手做）
- 吞吐：393 条 × 512 tokens 连续批处理约 3~5 分钟/轮（对比 Ollama 本机 1~3 小时、transformers 15~30 分钟）
- 关键细节：`chat_template_kwargs={"enable_thinking": False}` 必须显式关闭思考模式，否则输出混入思考文本污染评分
- 资源：单张 L20 足够（9B BF16 18GB + KV cache），其余卡可同时跑超参扫描训练

### 3.2 提示词条件（各跑一遍）

1. **zero-shot**：直接问
2. **few-shot**：从 train 集（非 test）抽 3~5 条同任务示例入 prompt——给底座最大的机会，这才是公平基线

解码统一：greedy（temperature=0），max_new_tokens=512。微调后模型用**完全相同**的解码与模板，保证可比。

### 3.3 自动指标（按任务类型）

我们数据的结构化程度允许大部分任务**自动评分**，不必全靠 LLM judge：

| 任务 | 指标 | 方法 |
|---|---|---|
| T1a/T1b/T2c（分级/孕妇） | 分类准确率 | 从输出抽取 大毒/有毒/小毒/未收录，对照 gold |
| **冲突药材 17 味专项** | 分级正确率 | 单列——底座最容易说错的点，也是微调最该提升的点 |
| T4d SMILES | 精确匹配率 | 规范化字符串比对（可升级 RDKit 规范化） |
| T4e/f CAS/PubChem | 精确匹配率 | 字符串精确 |
| T6（拒答） | 拒答正确率 | 应拒答的样本：含拒答标记且未编造数据；另有反例检查（不该拒答的 T1 是否被误拒） |
| T5（剂量对比） | 保守性检查 | 输出**不得**出现"超量/安全/不安全"的定性结论（自动正则 + judge 复核） |
| T3/T7（开放式） | LLM-as-judge 1~5 分 | judge 收到 gold 答案 + 评分 rubric（事实性/完整性/幻觉扣分项） |
| 全局 | **毒性误标率** | 把无毒药说成毒药、或分级说错的条数——医疗场景最危险的单一数字，单独报告 |

judge 用廉价强模型 API 即可（GLM/DeepSeek API），rubric 固定写入 prompt。

### 3.4 报告格式

`eval/results/baseline_{zeroshot,fewshot}.json` + `finetuned.json` → 汇总表：
每任务 × 每条件的准确率/得分，突出三行：冲突药材专项、毒性误标率、T6 拒答正确率。

## 四、微调配置基线（阶段 3 预案）

- 方法 QLoRA：lora_rank=16/32、alpha=2×rank、target=q,k,v,o,gate,up,down、lr=1e-4~2e-4、epochs=3、cutoff_len=1024（数据 p90 输出仅 154 字）
- 利用多 L20 并行扫 2~4 组超参，取 val 集最优
- 防过拟合检查：val loss 转折 + test 集 T6 拒答不退化（SFT 常见副作用是过拟合后拒答能力消失）
