# 方向 D · 指令数据设计（阶段 1）

> 数据构造前的任务类型与模板设计。目标：从现有 4 表 + 药典参考表构造高质量 SFT 数据，
> 重点训练**事实一致性**与**拒答能力**，而非流畅度。

---

## 一、设计原则

1. **可溯源**：每条样本的答案必须完全来自表字段，`meta` 记录来源表与主键，杜绝编造
2. **拒答优先**：医疗场景幻觉致命，专门构造"数据里没有"的样本（T6），教模型承认不知道
3. **模板多样化**：每个任务 3~5 个问法变体（正式/口语/英文），防止模型学模板而非学知识
4. **难度分层**：单跳问答 → 多跳检索 → 分析推理，逐层递进
5. **答案带来源口径**：分级冲突已统一按药典 2020 处理，答案中注明依据，训练模型给出可核查的回答

## 二、数据源盘点（当前可用）

| 来源 | 可用字段 | 备注 |
|---|---|---|
| `TCMTox_herb_clean.csv`（229 味） | 中文名/拼音/英文名/拉丁名、性、归经、药用部位、功效、主治、**分级（清洗后 72 味）**、临床毒性表现 | 新增 4 列：grade/source/conflict/original |
| `yd2020_toxic83.csv`（83 种） | 分级、**用法用量**、**注意事项（含十八反、孕妇禁忌）** | 清洗脚本副产品，安全用药问答的核心弹药 |
| `TCMTox_formula.csv`（1555 方） | 方名、处方、剂型、疾病、证候、功效 | 处方为**拼音+炮制前缀+投料量**，如 `Chao Qian Niu Zi 200g` |
| `TCMTox_ingredient.csv`（9377） | 成分英文名、SMILES、CAS、PubChem/DrugBank ID | 无草药关联（HBIN join 问题），只能做单表问答 |
| `TCMTox_target.csv`（7885） | 靶点名、UniProt、**毒性类型标注** | 全英文，需中英双语模板 |

### 两个关键事实（影响任务设计）

- **处方文本是拼音**：`Dai Huang 100g,Chao Qian Niu Zi 200g,...`。解析用 Herb 表 `Herb_pinyin_name` 做词典 + 炮制前缀剥离（Chao 炒/Zhi 制/Bao 炮/Yan 盐…）。解析器是 T3/T5 的前置，产出同时也是方向 B 需要的方剂-草药结构化。
- **处方剂量是投料量≠日服量**：`Zhu Sha 30g` 是制剂量，不能直接判"超药典 0.1-0.5g"。剂量对比类样本的答案必须说明这一区别，绝不输出"超量"结论——这本身就是一个防幻觉训练点。

## 三、任务类型与模板

### T1 单药毒性知识问答（主力，量最大）

覆盖字段：分级、性味归经、功效、临床毒性表现、药用部位、拉丁名。

| # | 模板（问法变体示例） |
|---|---|
| T1a | 中药{药}的毒性分级是什么？ |
| T1b | {药}有毒吗？毒性强不强？ |
| T1c | 请介绍{药}的性味与归经。 |
| T1d | {药}的临床毒性表现有哪些？ |
| T1e | What is the toxicity grade of {herb_en}? |
| T1f | {药}以什么部位入药？拉丁学名是什么？ |

示例：
```json
{"instruction": "附子的毒性分级是什么？", "output": "附子为有毒药材（《中国药典》2020年版）。内服一般炮制后使用，常用量3-15g，宜先煎、久煎。孕妇慎用；不宜与半夏、瓜蒌、天花粉、川贝母、白蔹、白及等同用。",
 "meta": {"task": "T1a", "src": ["TCMTox_herb_clean", "yd2020_toxic83"], "herb": "附子"}}
```

### T2 药典安全用药（高价值差异化）

覆盖字段：用法用量、注意事项（孕妇/配伍/特殊人群）。

| # | 模板 |
|---|---|
| T2a | 药典规定{药}的用量范围是多少？ |
| T2b | {药}有什么使用注意事项？ |
| T2c | 孕妇可以使用{药}吗？ |
| T2d | {药}和甘草能一起用吗？（十八反/药典禁忌） |
| T2e | 哪些毒性中药运动员需要慎用？ |

### T3 方剂毒性分析（多跳，需处方解析器）

处方文本 → 识别毒性药材 → 分级/禁忌汇总。

| # | 模板 |
|---|---|
| T3a | 分析方剂"一捻金"的处方，指出其中的毒性药材及其用量。 |
| T3b | 这个处方里有需要特别注意安全性的药吗：{处方文本}？ |
| T3c | 方剂"{方}"主治什么病？含哪几味毒性药？分别是什么分级？ |
| T3d | List the toxic herbs contained in the formula {Form_name_en}. |

### T4 靶点与毒性类型知识（英文表，双语模板）

| # | 模板 |
|---|---|
| T4a | 靶点{gene}与哪种毒性类型相关？ |
| T4b | Which targets in the database are annotated as neurotoxicity-related? |
| T4c | {gene}的UniProt编号是什么？它与哪些毒性标注相关联？ |

### T5 剂量对比分析（推理类，答案保守）

处方投料量 vs 药典用量，答案必须区分投料量与日服量。

| # | 模板 |
|---|---|
| T5a | 方剂"一捻金"中朱砂投料30g，药典规定其用量是多少？如何理解这个差距？ |

标准答案结构：给出药典日用量 → 说明处方数值为**制备总投料量**、非单次服用量 → 提示按成品分摊后仍需关注 → 不下"超量/安全"结论。

### T6 拒答与边界（防幻觉核心，test 集占比 ≥ 15%）

| # | 场景 | 期望行为 |
|---|---|---|
| T6a | 问库外药材（如"三七的毒性分级"——三七在库但药典未列毒性） | 明确"药典未将其列为毒性药材，库中亦无毒性分级记录" |
| T6b | 问完全不存在的中药（"灵芝草的靶点"） | 承认数据库无记录，不编造 |
| T6c | 问成分-草药关联（关系表缺失） | "暂无该关联数据"，不猜 |
| T6d | 问药品治疗建议 | 声明是知识库问答，建议咨询医师/药师 |
| T6e | 问清洗冲突项的旧标注（"川乌是小毒吗"） | 纠正：按 2020 药典为**大毒** |

### T7 反向检索/列表

| # | 模板 |
|---|---|
| T7a | 数据库中大毒中药有哪些？ |
| T7b | 哪些毒性中药孕妇禁用？ |
| T7c | 不宜与半夏同用的药材有哪些？为什么？ |
| T7d | 主治"食积"且含毒性药材的方剂有哪些？ |

## 四、数量估算与切分

| 任务 | 构造逻辑 | 预计条数 |
|---|---|---|
| T1 | 72 有分级 × 6 字段维度 × 4~6 变体 + 无分级药材的边界样本 | ~1,200 |
| T2 | 83 药典条目 × 5 变体 | ~400 |
| T3 | 解析成功的方剂（含毒性药子集优先）× 4 变体 | ~1,500 |
| T4 | 靶点采样 1,500 × 中英 2 变体 | ~3,000 |
| T5 | 处方-药典剂量交叉 | ~400 |
| T6 | 拒答/纠错/边界 | ~400 |
| T7 | 聚合查询 | ~200 |
| **合计** | | **~7,000** |

切分：train/val/test = 90/5/5，**按"药"和"方剂"分组切分**（同一药材的所有样本不跨集，防泄漏）；test 集中 T6 拒答类 ≥ 15%。

## 五、输出格式

JSONL，兼容 LLaMA-Factory / ms-swift 的 alpaca 与 sharegpt 双格式导出：

```json
{"instruction": "...", "input": "", "output": "...",
 "meta": {"task": "T1a", "src": ["TCMTox_herb_clean"], "key": "HERB000123", "lang": "zh"}}
```

`meta` 不参与训练，仅用于溯源与分任务评测。

## 六、实施顺序与待决问题

1. **先写处方解析器**（T3/T5 前置）：拼音词典匹配 + 炮制前缀剥离，产出 `formula_herbs.csv`（方剂-药材-剂量结构化），方向 B 也能直接复用
2. 按任务逐个实现构造器：T1 → T2 → T6 → T7 → T4 → T3 → T5（先易后难，拒答类提前）
3. 待决：
   - 炮制前缀清单（Chao/Zhi/Bao/Yan/Duan/Cu/Mi/Jiu…）需实测处方文本确定
   - 拼音变体（如 Dai Huang vs Da Huang）覆盖率需实测
   - T4 毒性类型字段的取值分布还没 profiling，构造前先看
   - 英文样本占比（建议 20~30%）

## 七、实际产出（2026-11-04）

构造器：`tcmtox-llm/scripts/build_sft_data.py`；产物：`tcmtox-llm/data/sft/`（t1~t7.jsonl + train/val/test.jsonl）。

| 任务 | 实际条数 | 备注 |
|---|---|---|
| T1 | 813 | a~f 六个子模板，按字段填充率出题 |
| T2 | 236 | 83 药典条目 + 孕妇/配伍展开 |
| T3 | 1200 | 仅含分级毒性药的方剂出题（1289 方中筛出） |
| T4 | 3026 | 靶点采样 1300 + 成分 SMILES/CAS/PubChem 800 |
| T5 | 674 | 投料量-药典用量交叉，答案保守不下结论 |
| T6 | 252 | a~e 五类拒答/纠错（扩大 T6d 至 105 条） |
| T7 | 33 | 分级/孕妇/配伍/方剂反查 + 数据库概况 |
| **合计** | **6234** | train 5512 / val 329 / test 393 |

**审计结果**：
- 实体泄漏：0 / 3640 组（同一药/方/靶点不跨 split）
- test 集 T6 占比 **22.1%**（设计要求 ≥15% ✓）
- 冲突药材口径验证：川乌=大毒、半夏=有毒、天仙子=大毒（均按药典）✓
- 语言分布（train）：zh 44% / zh-en 45% / en 11%
- 答案长度：p50=90 字，p90=154 字，max=855 字（T7 列表类）

**实施中的关键决策**：
1. **放弃 difflib 模糊匹配**（处方解析阶段即已确认危险：陈皮→蟾皮等误配），T3/T5 全部基于人工核实的 3 个拼音变体
2. **长英文字段不自动翻译**（临床毒性表现/功效/主治），以 zh-en 框架引用原文，防翻译错误注入训练数据
3. **聚合类答案口径诚实化**：T7a 明确"库内按药典标注 X 味"而非"药典收载 X 种"（药典 83 种未全部入库）
4. T3 的"识别出"措辞：处方解析仅覆盖毒性药表 229 味，答案明确"其余药味不在毒性中药集内"，不说"全部成分"

**遗留待办**：
- T6c 中 10 条泛化拒答模板 instruction 重复（"查询该成分的来源药材。"×10），是有意的行为训练，后续可加变体
- 关系表抓到后可扩充：成分-药材问答（T4 扩展）、药材-靶点毒性机制问答（T1/T4 扩展），预计 +3000~5000 条
